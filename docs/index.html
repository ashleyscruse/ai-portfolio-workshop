Pre-work

Do this before the session, about 20 minutes. Once Claude is installed, you don't have to figure out the rest yourself: copy each prompt into Claude and let it walk you through.

01

Get a paid Claude account

Go to claude.ai and sign up for the Pro plan or higher. The free plan doesn't include the coding tool we use.

02

Install the Claude desktop app

Download it from claude.ai/download, install it, and sign in. Stuck? Paste this into a chat at claude.ai:

I'm on a [Mac / Windows] computer. Walk me through downloading, installing, and signing in to the Claude desktop app, one step at a time. Wait for me to say "done" before giving the next step.
03

Install Node.js

Node.js is what lets you preview your site on your own computer. Paste this into a chat in the Claude app:

I'm on a [Mac / Windows] computer and I've never installed developer tools. Walk me through installing the LTS version of Node.js from nodejs.org, one step at a time, and wait for me to say "done" before each next step. Then show me how to check that it worked.
04

Download the starter folder

Go to github.com/ashleyscruse/portfolio-starter, click the green Code button, then Download ZIP. Unzip it somewhere easy to find, like your Desktop. You don't need a GitHub account.

05

Test it in the Code tab

In the Claude app, open the Code tab and choose your unzipped portfolio-starter folder. Then paste:

Check that Node.js and npm are installed and tell me the versions. Then run npm install and npm run dev in this folder, and tell me the address to open in my browser. Do not change any files. If anything fails, explain it in plain words and tell me what to do.
If you see a page in your browser, you're ready. Leave the rest for the session.
06

Gather your material

Put a headshot and any project images or charts in one folder. Then paste this into a chat to pull together the words:

I'm building a portfolio website. Interview me, one question at a time, about who I am and two or three projects I'd want to show (class work, research, posters, internships). After my answers, give me a short bio and a few sentences on each project that I can save and bring to the workshop.
This is a public website. No phone number, home address, student ID, or birthday.

Setup

01

Open your folder in Claude

In the Claude desktop app, open the Code tab and choose the portfolio-starter folder you unzipped. Claude can now read and edit the files in it.

02

Start your preview

Paste this, then open the address Claude gives you in your browser. Keep that tab open: it updates every time Claude changes a file.

Run npm install and then npm run dev in this folder. Leave it running and tell me the address to open in my browser.

The folder

A good AI session starts before you type a prompt. This folder is the AI's memory: anything written here, you never have to explain again.

FileWhat it does
AGENTS.mdStanding instructions: what the project is, where things are, the rules. Read it now; you can change any rule.
context/about-me.mdFacts about you. The AI is told to use only these, so it can't make things up.
context/style.mdHow the site should look and sound.
projects/One file per project, all the same shape. Copy _template.md for each new one.
images/Your photos and charts, named for what they show.
03

Fill your folder (10 minutes)

a. Open context/about-me.md and fill in what you can, using the bio from your pre-work. Blanks are fine; the AI will ask.

b. Open context/style.md and change anything you don't like.

c. For each project, copy projects/_template.md, rename it for the project (like projects/water-quality-poster.md), and fill it in.

d. Drag your headshot and project images into images/. Rename each for what it shows.

This is a public website. No phone number, home address, student ID, or birthday.

Prompts

Copy each one into Claude, in order. Type @ to point at a file by name. When Claude wants to change a file, read what it's changing before you approve.

P1

Orient

Make the AI read before it writes. If its summary is wrong, your files are unclear: fix the file, not the chat.

Read AGENTS.md and every file in context/ and projects/. In five bullets, tell me what you know about me and what is still missing. Do not write any code yet.
P2

Interview

Let the AI fill your gaps by asking you. Your answers end up in a file, so they're saved for every future chat.

Interview me to fill in what is missing in context/about-me.md. Ask one question at a time and wait for my answer. After five questions, update the file and show me what changed.
P3

Plan

Planning is cheap; rebuilding is not. Push back on anything you don't like before it builds.

Plan a one-page portfolio site that follows context/style.md. List the sections in order and what goes in each, in plain words. Wait for my OK before building anything.
P4

Build

Watch your preview tab: the site appears as Claude writes it.

Build the site from the plan: index.html and style.css at the top of the folder, following every rule in AGENTS.md. Use only facts from context/ and projects/ and images from images/. Where something is missing, leave a TODO comment and list the TODOs for me at the end.
P5

Feature a project

Point at just the file the job needs. Less context, better aim.

Make @projects/[your-project].md the featured project. Show its key results as a short row of numbers or highlights, and use the image listed in the file. Change nothing else on the page.
P6

Fix one thing

Describe what you see and where. You can also paste a screenshot into the chat. One fix per prompt.

On a phone-sized screen, [describe the problem and where it is]. Fix only that. Tell me which lines you changed.
P7

Remember

This is how the AI remembers between chats: decisions go in a file, not in your head.

Add the decisions we made today (colors, fonts, section order, anything else we settled) to the Decisions section of AGENTS.md, one line each with today's date.
P8

Check

Make the AI audit its own work against your rules before the world sees it.

Review index.html against AGENTS.md. List every rule it breaks and every fact on the page that is not backed by a file in context/ or projects/. Do not fix anything yet; just list them.

Context tips

People who get great results from AI aren't better at typing prompts. They're better at organizing what the AI reads.

  1. Write it down once, point to it forever. If you've typed the same explanation twice, it belongs in a file.
  2. Same shape every time. Every project file has the same headings, so the AI (and you) can find anything.
  3. Name things for what they are. water-quality-chart.png tells the AI what it is. IMG_2041.png tells it nothing.
  4. Point only at what the job needs. More context isn't better; the right context is. Use @ to point at one or two files.
  5. One job per chat. When the AI gets confused or starts going in circles, start a new session. It rereads your files and starts clean.
  6. Plan, then build. Ask for the plan first. Fixing a plan takes one sentence; fixing a website takes ten prompts.
  7. Make it ask, not guess. "Ask me" and "leave a TODO" are the two most useful phrases you have.
  8. Save decisions to a file. The chat forgets. AGENTS.md doesn't.
  9. Read before you approve. You're the editor. If you can't explain a change, ask the AI to explain it or undo it.
  10. Save points. When something works, make a copy of your folder. If the next change breaks everything, you can go back.

Put it online (optional)

Your site works on your computer today. When you're ready to share it, a free GitHub account puts it on the web. Paste this into Claude:

I want to publish this folder as a free website with GitHub Pages. I [have / don't have] a GitHub account. Walk me through it one step at a time, and wait for me to say "done" before each next step.

After today

Every time you finish something (a poster, a class project, a summer program), copy projects/_template.md, fill it in, and ask the AI to add it to your site. Five minutes, and your portfolio grows with you.
